# Spirit Fission — Orthogonal De-entanglement Protocol

> **Core Distinction:** **Slicing** cuts one homogeneous thing into smaller sequential steps (`Step 1 -> Step 2 -> Step 3`). **Spirit Fission** separates *distinct things obeying different governing laws* after they have accidentally fused into one repo, workflow, dataset, brief, or question.

---

## 1. The 4-Step Fission Protocol

### Step 1: Name the Fusion Symptom
Trigger Spirit Fission only when at least one concrete symptom is observed:
1. **Drag Asymmetry:** Changing or running a fast, low-risk part forces you to load, satisfy, or retest a slow, heavy part (e.g., a 15-minute update forced through a 10-gate campaign pipeline, or a `<50ms` runtime kernel bundled with offline mining).
2. **Rule Misfire Across Regimes:** A gate that protects quality in one regime destroys quality in another (e.g., courtroom claim-auditing catching real errors on locked cuts while prosecuting art direction in exploratory treatments).
3. **Contagious Blocking:** One unresolved `[UNKNOWN]` or unapproved downstream step freezes independent work that does not physically depend on it.
4. **Custody Contamination:** Restricted or environment-bound instance data (PII, employer text, tokens) is fused with reusable structural logic or evergreen rules.

### Step 2: Cut Along the 5 Canonical Cleavage Planes
Select only the plane(s) that match the observed symptom:
- **Plane 1 — Pace & Lifespan:** Evergreen kernel vs. domain playbook vs. ephemeral scratch; fast micro-update vs. multi-stage flagship.
- **Plane 2 — Control vs. Mechanism:** Orchestrator-producer judgment vs. deterministic, replaceable domain spoke (`<spoke>_{recognize,prepare,deliver}`).
- **Plane 3 — Epistemic Role:** `decision` (authority) vs. `evidence` (verified facts/selects) vs. `method` (non-evidentiary craft) vs. `[PROPOSED]` creative choices.
- **Plane 4 — Dependency & Certainty:** `independent_portions` (execute now) vs. `[PROPOSED DEFAULT]` (reversible assumption) vs. `[UNKNOWN — OWNER TO CONFIRM]` (exact blocked decision + owner).
- **Plane 5 — Custody & Topology:** Restricted instance data (redacted/ephemeral) vs. portable state machine and synthetic test fixtures.

### Step 3: Bind the Narrow Interface
Define explicitly:
1. **What crosses the seam:** A minimal typed contract (e.g., 3-tool MCP contract, hold table, or JSON schema).
2. **What is forbidden to cross:** No shared mutable internals, no raw lexical routing piped as authority, no PII leaking into portable models, and no craft guidance masquerading as clearance.

### Step 4: Run the Two-Sided Fission Proof
Never declare fission complete without proving both sides:
1. **Independence Test:** Each separated half runs, tests, or advances cleanly without importing, loading, or waiting on the other half.
2. **Recomposition Test:** One live end-to-end pass across the narrow interface confirms the halves still compose to deliver the full outcome.

## 2. Six-Substrate Reference Matrix

| Substrate | What Gets Accidentally Fused | Primary Plane(s) | Fission Output (Halves + Narrow Interface) | Observable Pass Criterion |
| :--- | :--- | :--- | :--- | :--- |
| **1. Ideas** | Vision + v1 wedge + v3 wishlist + build anxiety in one pitch | Pace + Dependency | Evergreen invariant + 1 `GREEN` vertical slice + parked future spokes | Slice 1 can be built and falsified today without v2/v3 scaffolding. |
| **2. Workflows** | Fast updates, templated ops, and flagship campaigns in one checklist | Pace + Authority | Speed tracks routed at intake (`Track A..D`) | A 15-min update finishes in 4 steps; flagship cuts still enforce timelock gates. |
| **3. Data** | Live PII/restricted text mixed with schemas and failure patterns | Custody + Lifespan | Ephemeral redacted pull + zero-PII topology model + synthetic fixtures | `0` restricted strings on disk; synthetic fixtures reproduce 100% of edge cases. |
| **4. Information** | Verified facts, approvals, craft methods, and art direction in one block | Epistemic Role | Tagged separation of `decision`, `evidence`, `method`, and `[PROPOSED]` | Craft never grants clearance; exploratory art direction is not prosecuted as testimony. |
| **5. Unknowns** | Hard blockers, reversible defaults, and independent work in one fog | Dependency & Certainty | `independent_portions` + `[PROPOSED DEFAULT]` + `[UNKNOWN — OWNER TO CONFIRM]` | Work advances immediately to the exact physical boundary of the unknown. |
| **6. Systems / Code** | Control plane, domain craft, and offline mining in one monolithic CLI | Control/Mechanism + Pace | Lean runtime hub (`<50ms`) + standalone MCP spokes (`recognize/prepare/deliver`) | Hub runs and tests green without spoke internals; spokes test independently. |

## 3. Skill Boundaries (Zero Overlap)
- **`spirit-fission`:** *De-entangles* a fused system, workflow, dataset, brief, or set of unknowns along the 5 cleavage planes into independent halves with a narrow contract.
- **`idea-crucible`:** Compresses *one* already-separated product/feature spark into a single bounded vertical build slice.
- **`negative-space`:** Audits omissions, subtracts non-essential surface area, and enforces mechanical AST/custody boundaries.
